Industrial Computing — Exercise 2

Distributed Predictive-Maintenance A2A System

A multi-process, multi-agent system with dynamic registry-based service discovery: five independent agents, each its own process (and, containerized, its own Docker container on its own port), collaborate over an A2A-style HTTP protocol to diagnose industrial equipment health.

Prepared by markusrussold@gmail.com · 2026-09-13 · Runtime verified: local processes + Docker Compose (5 containers)

Architecture

solid arrows = A2A /tasks/send calls · dashed = registry lookups performed fresh on every request

How the three agents collaborate

01
Vibration Analysis scores ISO 10816-style RMS velocity readings into a severity zone (B good D warn X danger) and an anomaly score.vibration-analysis
02
Thermal Analysis scores bearing/housing temperature readings against warning (80 °C) and critical (95 °C) thresholds, run concurrently with step 1.thermal-analysis
03
Maintenance Scheduling only executes once both scores exist — it combines them with operating hours into a priority, a concrete action, and a re-check interval. This dependency is what makes it a real pipeline, not three isolated calls.maintenance-scheduling

Dynamic registry lookup — verified end to end

The Orchestrator never hardcodes a peer's host or port. For every request it asks the Registry GET /lookup?capability=X and calls whoever answers. Two behaviors were captured live from the running Docker Compose system:

docker compose — 5 containers, then a diagnosis 
$ docker compose ps
